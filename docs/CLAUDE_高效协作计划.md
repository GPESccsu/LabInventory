# Claude 高效协作计划（低额度消耗版）

> 目标：让 Claude 一次性完成更多工作，减少你来回补充需求导致的 token 消耗。

## 1. 先做的仓库诊断（我已基于当前代码结构总结）

当前仓库已经具备较完整能力：
- 兼容 CLI/FastAPI/Streamlit 三入口。
- 库存、项目、BOM、预留/消耗、流水、schema-export、XLSX 交易导入都已具备。
- SQLite 初始化采用幂等 DDL，兼容老库自动补齐。

但仍有可显著提升“可维护性与可扩展性”的空间：
1. **测试覆盖不足**：缺少对关键命令（stock-in/out、reserve/consume、txn-import-xlsx）的自动化回归。
2. **变更风险高**：`backend/app/inv.py` 体量较大，CLI 参数定义、业务逻辑、DDL 混在一起。
3. **文档与执行规范分散**：README、PLAN、脚本说明有，但缺少“给 Claude 的标准任务模板”。
4. **验收标准不统一**：缺少每次任务固定输出格式（改动清单 + 风险 + 回滚 + 测试结果）。

## 2. 让 Claude 多干活的核心策略

### 策略 A：任务包模板化（一次发完整上下文）
你每次不要问“先看看”，而是直接给 Claude 一个完整任务包：
- 背景（业务目标）
- 约束（不能破坏的命令）
- 输入文件范围
- 输出物（代码/文档/测试/迁移）
- 验收命令
- 提交规范（commit + PR）

这样能显著减少多轮追问。

### 策略 B：强制“先计划后编码”
要求 Claude 首先输出：
1) 影响文件列表；2) 风险点；3) 测试清单；4) 回滚方案。
确认后再改代码，避免大改返工。

### 策略 C：按“可独立合并”的批次拆分
建议每次只做一类工作：
- 批次 1：测试基建与 smoke tests
- 批次 2：将 `inv.py` 中纯业务逻辑提取到 service 层
- 批次 3：XLSX 导入错误报告增强
- 批次 4：报表与导出

每批次都能独立回滚、独立发布。

### 策略 D：让 Claude 自己做自检闭环
在提示词里明确要求：
- 必跑命令（如 `python inv.py --help`、`pytest`、关键 CLI e2e）
- 失败时给出“失败原因 + 可执行修复建议”
- 输出“下一步可继续自动化的任务列表”

## 7. 你问的重点：如何给 Claude 写 prompt，才能“照指令干活”

下面给你 3 个“可直接复制”的版本，按你时间和预算选。

### A. 极简版（30 秒可发）
```text
你是本仓库执行代理，请严格按仓库 AGENTS.md 执行。

任务：{一句话目标}
范围：只允许修改 {文件/目录}
约束：不破坏现有 CLI 子命令和 --db 参数，不删表不改名

执行顺序：
1) 先输出计划（改哪些文件、风险、测试命令）
2) 再改代码
3) 运行验收命令并贴结果
4) git commit + 生成 PR 标题/正文

验收命令：
- python inv.py --help
- {你的业务命令1}
- {你的业务命令2}
```

### B. 稳妥版（推荐，返工最少）
```text
请作为 LabInventory 的资深维护者，在不破坏兼容性的前提下完成任务。

【目标】
{例如：为 stock-out 增加批量 CSV 导入并写入流水}

【必须遵守】
1. 严格遵守 AGENTS.md。
2. 保留现有 CLI 子命令/参数行为（尤其 --db、stock-in/out、proj-*）。
3. 数据库变更必须幂等（IF NOT EXISTS），旧库可自动补齐。
4. 不删除任何现有表/视图/触发器。

【输出步骤】
Step 1: 只输出计划（不改代码）
- 影响文件
- 风险点
- 回滚方案
- 验收命令

Step 2: 实施改动
- 按最小可合并批次提交
- 每批次后至少保证 `python inv.py --help` 可运行

Step 3: 交付结果
- 变更摘要（按文件）
- 测试结果（命令 + 通过/失败）
- 未完成项和下一步建议
- commit hash + PR 标题/正文
```

### C. 低额度版（让 Claude 先“只规划”）
```text
先不要改代码，只做“执行计划”。
输出：
1) 分阶段任务（Phase 1/2/3）
2) 每阶段影响文件（<=5 个）
3) 每阶段验收命令
4) 风险与回滚
5) 预估改动行数

我确认 Phase 1 后，你再开始改代码。
```

### 实操建议（最省 token）
1. **一条 prompt 只做一件事**（例如只做测试、只做导入、只做报表）。
2. **强制先计划**，你确认后再编码，能显著减少返工。
3. **固定验收命令**，每次都让 Claude 原样执行并贴结果。
4. **限制改动范围**（指定目录/文件），避免它“顺手大改”。
5. **要求输出失败项**，别让它只报喜不报忧。
